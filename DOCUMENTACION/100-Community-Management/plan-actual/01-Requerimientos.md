# 01-Requerimientos.md — Módulo 100: Community Management

## ID del Módulo
- **Código:** M100 (plan maestro: sección 99 — Community Management)
- **Carpeta:** `DOCUMENTACION/100-Community-Management/`
- **Dependencias:** M99 (Marketing), M102 (Bug Tracking), M101 (QA General)
- **Carácter:** Módulo de gestión de comunidad para comunicación con jugadores

## 1. Problema

El proyecto necesita un sistema de **Community Management** para gestionar la comunicación con la comunidad de jugadores, moderar canales, manejar feedback, gestionar expectativas y mantener un ambiente saludable. El juego es cozy y single-player, por lo que la comunidad se gestiona principalmente fuera del juego (Steam forums, Discord, redes sociales).

## 2. Requisitos Funcionales

| # | Requisito | Detalle |
|---|---|---|
| RF1 | Reglas comunitarias | Crear reglas comunitarias claras y accesibles |
| RF2 | Moderación | Crear sistema de moderación con roles y permisos |
| RF3 | Sistema de reportes | Crear sistema de reportes para contenido inapropiado |
| RF4 | Canales de feedback | Crear canales estructurados para feedback de jugadores |
| RF5 | Roadmap público | Crear roadmap público si conviene (opcional) |
| RF6 | Changelog público | Crear changelog público de actualizaciones |
| RF7 | Respuesta a dudas | Sistema para responder dudas de jugadores |
| RF8 | Identificación de bugs | Identificar bugs reportados por la comunidad |
| RF9 | Recopilación de sugerencias | Recopilar y categorizar sugerencias de jugadores |
| RF10 | Gestión de expectativas | Gestionar expectativas realistas sobre el juego |
| RF11 | Gestión de críticas | Gestionar críticas constructivas y destructivas |
| RF12 | Gestión de contenido tóxico | Moderar y eliminar contenido tóxico |
| RF13 | Gestión de spoilers | Gestionar y etiquetar spoilers |
| RF14 | Gestión de filtraciones | Gestionar filtraciones de contenido no público |
| RF15 | Gestión de impersonación | Gestionar casos de impersonación oficial |
| RF16 | Gestión de copyright claims | Gestionar claims de copyright en contenido de fans |
| RF17 | Comunicación proactiva | Comunicación proactiva sobre estado del desarrollo |

## 3. Requisitos No Funcionales

- Comunicación debe ser profesional y amigable (tono cozy)
- Respuesta oportuna a dudas y reportes (SLA de 48 horas)
- Transparencia sobre estado del desarrollo sin revelar fechas irreales
- Consistencia en tono y estilo de comunicación
- Escalabilidad para crecer con la comunidad
- Documentación de todas las interacciones relevantes

## 4. Criterios de Aceptación

1. Los 17 puntos de la sección 99 del plan maestro resueltos.
2. Reglas comunitarias documentadas y publicadas.
3. Sistema de moderación definido con roles y permisos.
4. Sistema de reportes implementado y accesible.
5. Canales de feedback estructurados (Steam, Discord, redes sociales).
6. Changelog público actualizado con cada actualización.
7. Proceso de respuesta a dudas documentado.
8. Sistema de triage de bugs reportados por comunidad.
9. Sistema de recopilación de sugerencias.
10. Directrices para gestión de expectativas, críticas, contenido tóxico, spoilers, filtraciones, impersonación y copyright claims.
