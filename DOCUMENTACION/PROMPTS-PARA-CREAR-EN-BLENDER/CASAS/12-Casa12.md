# Me decante por la Opcion 2

Guía general — Casas transitables y rutinas de NPCs en Godot
Esta guía reúne el sistema que venimos construyendo: modelos de casas, colisiones, navegación, muebles, puertas, colas y rutinas configurables.

Está pensada para seguirla por etapas. Primero hacé funcionar una casa con un NPC y una silla; después ampliá al resto.

Estado del proyecto: los scripts anteriores son una base de implementación, no una entrega ejecutada y verificada. Además, el generador de la choza está recortado en el contexto: necesitás recuperar su versión completa para generar los modelos desde Blender.

1. Qué incluye el sistema
El recorrido completo previsto es:

text

NPC fuera de la casa
        ↓
Inicia una visita según su perfil
        ↓
Solicita un lugar en la cola
        ↓
Espera su turno
        ↓
Abre la puerta y cruza
        ↓
Busca una silla disponible
        ↓
Reserva y camina a su aproximación
        ↓
Se sienta durante un tiempo
        ↓
Comprueba que puede levantarse
        ↓
Solicita turno para salir
        ↓
Cruza hacia fuera
        ↓
Termina o espera para repetir
El jugador puede:

Entrar y recorrer los interiores.
Interactuar con muebles.
Abrir y cerrar puertas.
Sentarse y levantarse.
Ocultar la cubierta al entrar.
Lo que todavía no está implementado
Conviene distinguir datos de personalidad de acciones reales:

“Lector” todavía significa una variante de selección y duración del asiento; no reproduce lectura.
“Desayunador” no consume comida.
Las camas, cocinas y mesas siguen siendo puntos de interacción básicos.
No hay horarios globales, necesidades, inventarios ni elaboración.
La navegación no descubre automáticamente todas las puertas de una ruta.
La torre de la mansión sigue necesitando revisión arquitectónica.
2. Correcciones importantes antes de integrar
La última entrega de perfiles tenía algunas inconsistencias. Corregilas antes de probar.

2.1. La rutina actual solo utiliza sillas
La selección convierte los puntos a:

gdscript

var silla := valor as SillaCasa
Por tanto, no puede elegir camas, mesas o sofás básicos, aunque sus tipos aparezcan en PerfilVisita.

Por ahora configurá:

text

Tipos preferidos = ["SILLA"]
Podés conservar el campo para ampliaciones futuras, pero no presentarlo como soporte ya implementado.

Además, si todas las candidatas son SILLA, aumentar su peso de 1 a 5 para todas no cambia la selección relativa entre ellas.

2.2. Corregir el nombre de la variable de estado
En el rechazo por cola larga:

gdscript

_estado = Estado.TERMINADA
debe ser:

gdscript

estado = Estado.TERMINADA
2.3. Consultar la cola mediante un método
En GestorPasoPuerta, añadí:

gdscript

func get_tamanio_cola() -> int:
	return _cola.size()
Desde la rutina:

gdscript

var gestor := cruce.gestor
Usá:

gdscript

gestor.get_tamanio_cola()
No necesitás otra referencia exportada gestor_paso: podría terminar apuntando a un gestor diferente.

Este conteo incluye solicitudes pendientes, no al usuario activo.

2.4. Permitir siempre el primer intento de levantarse
La versión anterior impedía levantarse si el perfil no permitía reintentos. Eso no es correcto: sin reintentos significa un intento inicial, no cero.

Reemplazá _intentar_levantarse() por:

gdscript

func _intentar_levantarse() -> void:
	var limite := 1

	if perfil.reintentar_salida_asiento:
		limite = maxi(1, perfil.intentos_maximos_salida)

	if _intentos >= limite:
		_detener(
			"No se pudo liberar la salida del asiento "
			+ "tras %d intentos." % _intentos
		)
		return

	_intentos += 1
	_espera = maxf(0.2, intervalo_reintento)
	_asiento.pedir_levantarse()
Aquí intentos_maximos_salida cuenta intentos totales, incluido el primero.

2.5. Evitar tiempos negativos
En PerfilVisita:

gdscript

func obtener_tiempo_sentado(rng: RandomNumberGenerator) -> float:
	return maxf(
		0.1,
		tiempo_sentado_base
		+ rng.randf() * maxf(0.0, tiempo_sentado_variacion)
	)


func obtener_pausa_exterior(rng: RandomNumberGenerator) -> float:
	return maxf(
		0.2,
		pausa_exterior_base
		+ rng.randf() * maxf(0.0, pausa_exterior_variacion)
	)
La variación es aditiva: 8 + variación 2 produce entre 8 y 10 segundos.

4. Qué hace cada componente
Componente	Responsabilidad
CasaTransitable	Instanciar ALTA, generar colisiones, detector y rampa
InteriorCasa	Leer JSON y crear puntos de muebles
PuntoMueble	Identificación, disponibilidad y reserva básica
SillaCasa	Aproximación, pose y salida del asiento
NavegacionCasa	Generar navegación inicial desde colisiones
PuertaCasa	Hoja móvil, colisión, barrido y apertura
GestorPasoPuerta	Lugares de espera y turnos compartidos
ActorAsiento	Alineación, animación y salida comprobada
AccionMueble	Caminar hasta la silla y entregar control al asiento
CrucePuerta	Esperar turno, abrir y cruzar
RutinaCasa	Coordinar una visita completa
PerfilVisita	Tiempos y preferencias configurables
La regla central es:

Un solo componente debe mover al personaje en cada etapa.

text

8. Preparar las sillas
Cada silla necesita tres datos diferentes:

text

Centro del mueble
Aproximación caminable
Pose de raíz del actor
Salida comprobable
Ejemplo de ajuste:

JSON

{
  "SILLA": {
    "offset": [-0.65, 0.0, 0.0],
    "altura_objetivo": 0.65,
    "distancia_interaccion": 1.6,
    "asiento": {
      "offset_raiz": [0.0, 0.0, 0.0],
      "giro_grados": -90.0,
      "offset_salida": [-0.65, 0.0, 0.0],
      "tolerancia_aproximacion": 0.35
    }
  }
}
Estos valores son orientativos para la choza.

offset_raiz no es la altura del asiento. Es la posición de la raíz del personaje compatible con su animación.

En casas 2–5 copiá los identificadores exactos del informe, como:

text

SILLA_3
SILLA_4
No supongas que todas tienen un identificador llamado SILLA.

9. Preparar puerta y cola
Puerta
La hoja debe:

Quedar dentro del vano.
Abrir hacia una zona libre.
No tocar muebles.
Tener el barrido configurado para detectar a los personajes.
Probá primero la entrada sin hoja. Si el personaje se traba contra el cimiento o la rampa, resolvelo antes de añadir lógica de puerta.

Cola
Los marcadores de cola deben quedar:

Fuera del barrido, incluida la cápsula completa.
Fuera del eje de circulación.
Separados entre sí.
Sobre navegación.
Los marcadores ESPERA_INTERIOR y ESPERA_EXTERIOR son destinos de finalización del cruce; no deben coincidir con lugares de cola.

En GestorPasoPuerta:

text

Puerta              → PUERTA_PRINCIPAL
Lugares exteriores  → COLA_EXT_01, COLA_EXT_02
Lugares interiores  → COLA_INT_01
Un gestor por puerta; todos sus NPCs comparten esa misma instancia.

10. Conectar los componentes del NPC
Componente	Referencias
ActorAsiento	Actor, collider, controlador habitual, animaciones
AccionMueble	Actor, ActorAsiento, AgenteMuebles
CrucePuerta	AccionMueble, puerta, gestor, destinos interior/exterior
RutinaCasa	CrucePuerta, InteriorCasa, NavegacionCasa, perfil
El controlador habitual es el nodo que ejecuta el movimiento normal. No asignes como controlador ninguno de estos coordinadores.

Durante la visita, RutinaCasa mantiene ese controlador suspendido. Al finalizar, restaura sus callbacks originales.

Desactivá los scripts antiguos de prueba. No deben coexistir con la rutina dando órdenes al mismo actor.

12. Rechazo por cola larga
Dejá esta opción desactivada durante las primeras pruebas:

text

Probabilidad rechazo cola larga = 0
Cuando la habilites, definí claramente su resultado:

Abandonar la rutina: pasar a TERMINADA y devolver control.
Esperar y volver a evaluar: pasar a PAUSA, conservando el bloqueo habitual.
No emitas visita_terminada si nunca entró. Es preferible añadir:

gdscript

signal visita_omitida(motivo: String)
Y emitir:

gdscript

visita_omitida.emit("Cola demasiado larga.")
La evaluación también debería hacerse una vez por decisión de visita si querés una probabilidad interpretable. Repetir el sorteo en cada reintento aumenta la probabilidad acumulada de desistir.

14. Fallos y recuperación
Problema	Qué revisar
NPC no abre la puerta	Cápsula dentro del barrido o turno no concedido
NPC choca con puerta cerrada	Otro script ordena una ruta fuera del sistema
Cola no avanza	Primer usuario no llegó, barrido ocupado o cancelación dentro del vano
No encuentra silla	Tipo, identificadores, pose, salida y disponibilidad
No llega a aproximación	NavMesh, tolerancias, muebles u obstáculos
No se levanta	Suelo de salida, máscara física y espacio para el collider
Techo reaparece al sentarse	Fijación del actor interior no conectada
NPC se mueve estando sentado	Otro nodo, timer o animación mueve la raíz
Rutina parece ignorar perfil	Variables antiguas todavía usadas en el script
Recuperación prevista:

gdscript

# Después de retirar un obstáculo del asiento:
rutina.reintentar_salida_del_asiento()

# Después de comprobar el lado en que quedó el actor:
rutina.reanudar_desde_posicion(true)  # Dentro
rutina.reanudar_desde_posicion(false) # Fuera

# Actor de pie y componentes libres:
rutina.devolver_control_tras_revision()
No descargues la casa ni elimines componentes con acciones activas. La cancelación global segura sigue pendiente.

Resultado final de esta fase
La base queda organizada en tres niveles:

text

CASA
Geometría + física + navegación + puerta + muebles

PERSONAJE
Movimiento coordinado + asiento + cruce + rutina

PERFIL
Tiempos + preferencias compatibles + política de espera
El punto de control más útil ahora es una choza, dos NPCs y una silla bien ajustada. Cuando esa prueba complete varios ciclos sin bloqueos, conviene ampliar a otras casas y luego añadir actividades reales, horarios y necesidades.
