## Resumen

Primera tarea del backlog propio kimi-k3 (M106 Seguridad, T-001). Se implemento la
**prevencion de economia adulterada (RF11)** en el `SecurityManager` (autoload), reutilizando el
catalogo data-driven existente. Se verifico con el binario real Godot 4.7.2 headless.

**Blocker transversal resuelto antes de poder verificar:** el autoload M107
(`backup_manager.gd`, de mimo-v2.5 Log 1068) estaba roto con codigo de **Godot 3**
(`ZIPWriter.open()` estatico, `write_file(path,bytes)`) que no compila en Godot 4.x →
contaminaba stderr de TODOS los runs headless con SCRIPT ERROR (falso-verde masivo, leccion 28).
Hy3 ya lo habia detectado (Log 1072, QA de M118) pero no lo reparo. Se aplico un fix quirurgico
de compilacion (sin tocar la logica de M107) y se documento como BUG-058 + E-22.

- **Archivo:** `game/isla-ancestral/scripts/security/security_manager.gd`
- Nuevo metodo que valida la economia de un jugador contra el catalogo
  (`data/security/security_policies.json` → `restricciones`: `max_plata` 999999,
  `max_objetos_inventario` 99, `max_nivel` 50) via `validar_max()`.

### 3. Fix transversal M107 (BUG-058 / E-22) — desbloqueo del boot headless
- **Archivo:** `game/isla-ancestral/scripts/backup/backup_manager.gd` (5 sitios, solo compilacion)
  1. `zip_available()`: `ClassDB.class_exists(&"ZIPWriter")` → `&"ZIPPacker"`.
  2. `_comprimir_directorio()`: `ZIPWriter.open(...)` estatico → `var writer := ZIPPacker.new()` +
     `writer.open(zip_path, ZIPPacker.APPEND_ADDINZIP)` (APPEND_CREATE → APPEND_ADDINZIP).
  3. `_agregar_dir_a_zip()`: `write_file(path, bytes)` → `start_file(path)` + `write_file(bytes)`
     (patron correcto Godot 4.x, igual que `cicd_manager.gd` M118).
  4. 6 inferencias `var x := cat.get(...)` (Variant) → tipo explicito `str(...)`/`bool(...)`.
