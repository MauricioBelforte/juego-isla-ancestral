## 2. Fix aplicado (H10 / BUG-132)

### 2.1 Causa medida
`mining_vein_catalog.gd:78` hacia `drop_entry.item_id = String(def_id)`: el drop usaba el
**id de la VETA** (p.ej. `veta_cobre`), que **no es un item**. `ItemDatabase` (M159) carga
solo `res://data/items/*.tres` (121 archivos) y no existe ningun `veta_*.tres` -> la
recompensa de minar era un **item fantasma** (sin nombre/icono/valor), inutil para crafting
(M16) o venta (M36/M38). Contra `03-Diseno.md:234`.

### 2.2 Cambios (3 archivos)
1. `game/isla-ancestral/data/mining/ores.json` - agregado `"item_id"` a las 6 vetas con el
   mapeo autorizado por el director:
   | veta | item_id |
   |---|---|
   | veta_cobre | mineral_cobre |
   | veta_hierro | iron_ore |
   | veta_oro | ancient_crystal |
   | veta_cristal | crystal |
   | veta_ancestral | fragmento_ancestral |
   | veta_polvo_estrellas | ancient_crystal |
   Los 6 ids verificados contra `data/items/` (121 `.tres`): los 5 nombres existen como
   `data/items/<id>.tres`. JSON valido (`json.loads` OK). 2470 B, LF, sin BOM.
2. `game/isla-ancestral/scripts/mineria/mining_vein_catalog.gd:78` ->
   `drop_entry.item_id = String(data.get("item_id", def_id))` (fallback = id de veta, para
   no romper si falta la clave). 4364 B, LF, sin BOM.
3. `game/isla-ancestral/scripts/mineria/test_mineria.gd` - bloque nuevo `drops_resuelven`
