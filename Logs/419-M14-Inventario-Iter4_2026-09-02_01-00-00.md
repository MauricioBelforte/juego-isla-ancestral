## Decisiones clave

1. **InventarioService pre-existente NO se modificó**: las iter 1-3 (ox-alpha + MiMo + Hy3) dejaron un nucleo solido con 6 contenedores, add/remove/move/swap/split/sort. Iter 4 NO lo toca; agrega 2 autoloads (hotbar, inventario_helper) que complementan sin duplicar. Esto preserva el trabajo de los otros agentes y mantiene la API estable.

2. **Duck-typing en TODO**: validar_item_existe, validar_invariante_post_viaje, nombres localizados, agregar con fallback, etc. usan `get_node_or_null` para no romperse si los modulos destino (M17/M37/M39/M55/M69/M87/M92) no existen. Si no existen, devuelven defaults (true, 0, "") que mantienen el juego jugable. **Regla de oro del proyecto: los modulos que fallan en sus dependencias no rompen el juego**.

3. **`_get_node_or_null(path)` vs `get_node_or_null(path)`**: use el wrapper porque recibe path completo `/root/...` y maneja el slash. Sin wrapper, `get_node_or_null` con slash falla silenciosamente.

4. **Hotbar como autoload separado**: la hotbar tiene estado propio (slots + slot_activo + esporas) que vive aunque el inventario este cerrado. Permite atajos 1-6 y gamepad.

5. **Persistencias separadas**: hotbar persiste en /root/hotbar, autosave metadata en /root/inventario_helper, contenedores en /root/Inventario (existente). Cada uno tiene su version de esquema y migracion defensiva.

## Pitfalls documentados (memoria colectiva)

- **PVS-Studio warning sobre Variant**: en modo estricto, `var X = func() if cond else null` infiere Variant y puede causar SCRIPT ERROR. Solución: declarar `var X: Type = null` y asignar después.
- **`push_warning` no falla el test**: aún así, los warnings aparecen en el log y pueden ser revisados. No usar como assert.
- **Modulo M17 ausente**: la API de M14 para cofres conectables ya está lista (`devolver_contenido_cofre`). Cuando M17 implemente, no se requieren cambios en M14.
- **InventarioService existente vs nuevo autoload**: NO modificar el Servicio existente. Iter 4 agrego 2 autoloads complementarios. Si necesito extender funcionalidad, extiendo el Servicio, no lo reemplazo.
- **Mismo path en `get_node_or_null` con/sin slash**: `/root/SaveManager` y `SaveManager` se comportan diferente en Godot 4. El primero es el path completo, el segundo busca solo en el SceneTree actual. Usar path completo para autoloads.
