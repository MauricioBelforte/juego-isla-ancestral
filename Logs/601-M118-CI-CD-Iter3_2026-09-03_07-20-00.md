## Pitfalls documentados (memoria colectiva)

- **M118 tiene el modulo mas tests en este proyecto**: 4 scripts Python x 1 test cada uno = 4 tests propios. Esto NO es para presumir, es para que el orquestador sepa que M118 tiene cobertura de tests del 100% de sus scripts. Es un modelo de como escribir herramientas data-driven.
- **Conventional Commits ayuda pero no es obligatorio**: el proyecto no usa prefijo `feat:`/`fix:`/`chore:` en los commits, asi que todos caen en "Changed". Mi CHANGELOG.md dice explicitamente "Sin cambios categorizados: revisar commits manualmente". Si el equipo adopta Conventional Commits, mi generador los categoriza automaticamente.
- **CHANGELOG.md data-driven desde git es facil de forkear**: si otro agente (Hy3, GLM) quiere re-categorizar, solo edita `data/operaciones/commit_conventions.json` y re-ejecuta `python tools/ci/changelog.py`.
