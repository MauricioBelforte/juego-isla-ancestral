## Estado de Blender (CRÍTICO)
- Proceso Blender PID 26224 sigue vivo pero el **socket 9876 no escucha** (connections=[] en psutil).
- Causa: ejecuté `bpy.ops.wm.read_factory_settings(use_empty=True)` en `bpy_cliente.execute_code` para probar el pipeline; ese reset **mata el listener del addon BlenderMCP** y el addon no se relanza solo. El socket requiere re-click en "Connect to MCP server" del panel del addon, o reiniciar Blender con el último .blend abierto.
- **Lección:** NO usar `wm.read_factory_settings` desde el socket MCP. Para "empezar limpio" dentro de un script, usar la limpieza idempotente (remover todos los objetos/datos con `users==0`) que ya hacen los scripts `crear_*_lowpoly.py`. Documentar en la guía.

## Hallazgo / error nuevo: E-14 (provisional)
- **Síntoma:** Tras `bpy.ops.wm.read_factory_settings()` ejecutado vía socket MCP, Blender sigue vivo pero `127.0.0.1:9876` deja de escuchar.
- **Causa:** el addon BlenderMCP vive como un atributo `bpy.types.blendermcp_server` con su socket TCP. `wm.read_factory_settings()` resetea `bpy.types` y elimina ese atributo; el server thread se queda en un estado inconsistente.
- **Solución provisional:** el usuario debe re-click en el botón del panel N → BlenderMCP → "Connect to MCP server" para relanzar el server. Si no, cerrar y reabrir Blender.
- **Solución definitiva (a documentar):** NO usar `wm.read_factory_settings` desde el socket. Cada `crear_*_lowpoly.py` ya hace su propia limpieza idempotente.
