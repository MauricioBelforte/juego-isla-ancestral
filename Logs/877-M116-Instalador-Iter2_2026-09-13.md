### 4. Preset de exportación Windows (desbloquea M117)

`game/isla-ancestral/export_presets.cfg` sólo tenía el preset `Web`. M117 (`build_targets.json`) exige presets `Windows`/`macOS`/`Linux/X11` — por eso sus propios comentarios de test decían *"los targets piden Windows/macOS/Linux que NO existen -> errores esperados en dev"*. Se añadió el preset `Windows` (`platform="Windows Desktop"`, `export_path="../build/windows/isla-ancestral.exe"`, `embed_pck=true`, `x86_64`). Verificado: Godot lee **2 presets**, test M117 sigue 14/0. Queda pendiente macOS/Linux (ajeno a M116).

### 5. Validador headless + test adversarial (anti-regresión)

| Archivo | Qué es |
|---|---|
| `game/isla-ancestral/scripts/build/validador_instalador.gd` (`class_name ValidadorInstalador`) | 11 familias de reglas **V1..V11**: presencia de artefactos, BOM (§28), CRLF en `.ps1/.iss/.bat`, preset Windows válido, coherencia de `export_path`, secciones obligatorias de Inno, asociación de archivos, preservación de datos de usuario, manifest de reparación, variables de firma. `static validar(ruta_repo) -> Dictionary` + `formatear_informe()` |
| `game/isla-ancestral/scripts/build/test_instalador_m116.gd` (`extends SceneTree`) | Bloques A–G con fixtures **en memoria** (sin copiar árboles), marcadores `_fin()` y aserción de todos los bloques. **15 checks, 0 fallos, 3/3 runs, 0 SCRIPT ERROR** |

El test **inyecta 5 fallos distintos** en los fixtures (BOM, CRLF, preset ausente, sección Inno faltante, borrado de datos de usuario) y exige que el validador **detecte cada uno**. Un validador que devolviera siempre "OK" no podría pasar: es verificación adversarial, no tautológica.

## Bugs reales encontrados y corregidos

### Bugs del instalador (encontrados por el smoke)

1. **`[ERROR] se requiere x64 (detectado )`** — `$env:PROCESSOR_ARCHITECTURE` está **vacío** en este host. Corregido con `[System.Environment]::Is64BitOperatingSystem` / `Is64BitProcess`.
2. **`uninstall_windows.ps1` moría antes de imprimir nada** — `$env:APPDATA` es `null`, `Join-Path` lanza excepción y `$ErrorActionPreference="Stop"` aborta el script. Corregido con `[Environment]::GetFolderPath("ApplicationData"/"LocalApplicationData")`.

### Bugs propios del validador (auto-detectados)

1. **V7 comparaba rutas equivocadas** — `_valor_cfg` leía el **primer** `export_path` del archivo (el del preset Web). Añadido `_export_path_windows()` que itera por `[preset.N]` y filtra por `platform="Windows Desktop"`.
2. **`simplify_path()` no resolvía `..\` con backslashes** — añadido `_norm()` que normaliza `\`→`/` antes de simplificar.
3. **Falso positivo de V8** — mi propio comentario `;` en `[UninstallDelete]` contenía las palabras "savegames/config". `_bloque()` ahora descarta las líneas de comentario `;` antes de comprobar patrones prohibidos.

### Errores de proceso míos

1. `InitializeSetup` mal declarado (dos funciones separadas) — Inno sólo llama `InitializeSetup(): Boolean` → fusionado.
2. Orden de `#include` — `system_requirements.iss` consumía `VersionPrevia` de `update.iss` pero se incluía antes → reordenado (`update.iss` primero; Pascal Script no tiene referencias hacia adelante).
3. Script de test colgado por timeout — `_repo_falso()` copiaba `scripts/` completo 5× → sustituido por fixtures en memoria.

## Restricciones del host (documentadas para futuros ciclos)

Este host **no** captura stdout nativo desde PowerShell ni permite crear procesos hijos, y las variables `$env:` pueden venir vacías. Receta que sí funciona: ejecutar en proceso neutralizando `exit` (`(?m)^exit (\d+)\s*$` → `$$global:RC = $1; return`), capturar con `*>&1` y volcar el resultado a un archivo temporal.
