## Resumen

Novena tarea del backlog propio kimi-k3 (M106 Seguridad, T-009). Se disenaron las **bases de
datos separadas por entorno** (RF4) extendiendo el catalogo de entornos y se implemento un
**validador de separacion** que evita el error clasico de seguridad: dev/staging apuntando a
produccion. Verificado con el binario real Godot 4.7.2 headless.

## Cambios Realizados

### 1. Catalogo de entornos extendido
- **Archivo:** `game/isla-ancestral/data/security/security_environments.json`
- Nuevos campos por entorno: `bd_host` (localhost / staging-db / db) y `bd_credencial_origen`
  (`env_local` dev / `env_sistema` staging / `secret_manager` prod).

### 2. NUEVO `security_database_config.gd` (RefCounted, sin class_name, via preload)
- **Archivo:** `game/isla-ancestral/scripts/security/security_database_config.gd`
- `config_bd()` -> `{entorno, nombre, host, credencial_origen}` del entorno activo.
- `validar_separacion()` -> Array de violaciones ([] = OK). Reglas: dev/staging no pueden usar la
  `base_datos` ni el `bd_host` de prod; nombres de BD distintos entre entornos; prod exige
  `secret_manager` (nunca `env_local`).
- `es_separacion_valida()` -> bool.

### 3. NUEVO `test_security_m106_database.gd` (guardianes anti-falso-verde)
- 15 checks: config_bd por entorno (dev localhost/env_local, prod secret_manager/host distinto),
  separacion valida en el JSON real, nombres dev!=staging!=prod, invariantes de credencial
  (prod no env_local, dev si env_local, staging env_sistema).

## Leccion (documentada)

Indexar un `Dictionary` (`config_bd()["nombre"]`) devuelve `Variant` sin tipo para inferir ->
`var x := ...` es parse error con warnings-as-errors. Usar `var x: String = str(...)`. (3 SCRIPT
ERROR en la 1ra corrida, corregidos.)
