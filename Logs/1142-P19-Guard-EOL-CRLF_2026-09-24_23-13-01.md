## Resumen

Se creo `scripts/editar_crlf.py` (**437 lineas**, versionado) — la herramienta
permanente de edicion de markdown que hace **imposible romper el EOL**. El defecto
que previene es **M-03**: editar un archivo con un editor que normaliza el salto de
linea y convertir **todas** las lineas de CRLF a LF (o al reves). El sintoma es
invisible en el contenido: `git diff` marca el archivo **entero** como cambiado.

## Por que existe (el problema real)

En el repo, `autocrlf=true`, asi que el **blob** va en LF y el **worktree** puede
quedar en CRLF. Medir el EOL "a ojo" o con `grep` **miente** (trampas 84-85): la
unica medicion valida es `git ls-files --eol` (blob vs worktree) mas un conteo de
bytes crudo. Un helper que reescribe el archivo entero con `open(w)` es exactamente
la forma de provocar M-03 sin querer.

## Cambios Realizados

### Que hace

Edita **por reemplazo de fragmento**, no reescribiendo el documento: mide el EOL
predominante, hace la sustitucion y **vuelve a escribir conservando el esquema de
EOL original**. CLI:

```
python scripts/editar_crlf.py <ruta> [--ver]
    [--reemplazar VIEJO NUEVO] [--insertar-despues ANCLA TEXTO]
    [--anexar TEXTO | --anexar-archivo RUTA] [--eol auto|crlf|lf] [--selftest]
```

## Evidencia (re-medida el 2026-09-24)

- `git cat-file -e HEAD:scripts/editar_crlf.py` -> **versionado** (trampa 98).
- `python scripts/editar_crlf.py --selftest` -> **16/16 casos, exit 0** (medido hoy).
- **Probado EN ROJO** por inyeccion: con la regla de conservacion desactivada ->
  **4 FALLO, exit 1**. Un selftest que solo se prueba en verde no protege nada.
- **Exit code propio de ceguera:** archivo ausente / 0 bytes / directorio ->
  **exit 3** (trampa 100 aplicada a la edicion: "no pude mirar" no es "esta bien").
- CLI: forzar LF sobre un archivo CRLF -> **exit 1 y el archivo queda
  byte-identico** (se niega a romperlo).
- Smoke test sobre el repo real: **335 CRLF -> 339** (0 LF sueltos);
  `ESTADO-PARALELO.md` (2797 CRLF + 1 CR + 2 NUL) -> **conserva los 3**;
  `CHECKLIST-GLOBAL.md` (LF puro + 1 NUL) -> **sigue LF puro**.

## Dos defectos propios, encontrados probando y corregidos ANTES de commitear

1. **Falso positivo (es M-06):** normalizaba el **documento entero**, asi que
   `--reemplazar "a" "A"` en un archivo **mixto se bloqueaba a si mismo** —
   cualquier edicion legitima era rechazada. Corregido: normaliza **solo el
   fragmento**. *Un guard demasiado ancho tambien es un defecto: no solo deja pasar
   lo malo, tambien bloquea lo bueno.*
2. **Fixture que no podia fallar:** el caso "el ancla aparece 2 veces" usaba un
   texto donde aparecia **una** vez, asi que la asercion era infalsable. Lo pesco el
   propio selftest (16/16 -> 1 FALLO) al correrlo despues de tocar el codigo.

## Premisa vencida (importa para el proximo)

El pedido original decia que `CHECKLIST-GLOBAL.md` tenia **"211 CRLF + 10 LF"**.
Medido: **ya no** — es **LF puro + 1 NUL**. El helper **preserva lo que haya**, asi
que la premisa vencida no invalida la herramienta; si invalida cualquier test que la
fijara. Es la leccion de siempre: medir la premisa, no heredarla.
