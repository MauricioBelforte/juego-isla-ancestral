## API nativa (MEDIDA, no supuesta)

`ClassDB.class_get_method_list("VoxelTerrain")` en Godot 4.7.2 + Voxel Tools:

```
voxel_to_data_block(voxel_pos: Vector3) -> Vector3i
has_data_block(block_position: Vector3i) -> bool
get_data_block_size() -> int
```

Ese es el contrato correcto ("¿hay data block en esta zona?"). El guard es **conservador**: sin
terreno (modo lógico) → no bloquea; sin esa API (VoxelTools distinto) → no bloquea. Solo rechaza
cuando la API responde y dice que no hay data block.

## Decisión de diseño (motive del guard)

El guard va **ANTES** de la validación, no después: si fuera después, el jugador vería *"sin
soporte"* (motivo **permanente**) en vez de *"el terreno de esa zona todavía no está cargado"*
(motivo **temporal**: el chunk se carga solo y el reintento funciona sin cambiar de celda). Es la
misma lógica que ya se aplicó con `SIN_ESPACIO` en el almacenamiento.

Además, el rechazo **no deja nada a medias**: no se registra la estructura, no se escribe ningún
voxel, no se cobra el costo; al mover, el origen **sigue en su sitio**.
