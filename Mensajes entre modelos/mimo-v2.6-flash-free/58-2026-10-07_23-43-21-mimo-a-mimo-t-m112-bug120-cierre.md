## 2. BUG-120 — causa raíz y fix

**Reproducción:** `godot --headless -s res://tests/run_tests.gd` → `EXIT 0` +
`RESULTADO: EXITO — Todos los tests pasaron` con **0 tests**.

**Causa:** la v1 hacía `GdUnitCmdTool.gd -- --path res://tests --verbose`.
`CmdArgumentParser.parse()` descarta hasta el nombre de la tool usando
`OS.get_cmdline_args()`, y Godot **no mete en ese array lo que va después de
`--`** (eso va a `get_cmdline_user_args()`). El parser ve solo `["-s", "…"]` →
`GdUnitResult.empty()` → `show_help()` → `quit(RETURN_SUCCESS)` = exit 0 sin
correr nada, y la v1 celebraba. Verificado con 2 probes (ya borrados):
`PROBE_ARGS` imprimía el array **sin** nada de después de `--`.

**Fix (`run_tests.gd` v2c):**
- Descubre `tests/**/test_*.gd` (excluye `helpers/`), clasifica SceneTree vs
  GdUnit4, corre **suite por subproceso** con salida a archivo (patrón M24:
  `OS.execute` no captura el stdout de un hijo Godot en este build).
- **Timeout 180 s (GdUnit 300 s) + `taskkill /T /F`**: sin esto, un SCRIPT ERROR
  que aborta una suite sin `quit()` deja el runner colgado (pasó en vivo).
- GdUnit4 con invocación correcta: `-a <dirs> --ignoreHeadlessMode`, **sin `--`
  ni `--path`** (sin el flag, GdUnit sale 103).
- **Guardas:** `EXIT 0` solo si suites ejecutadas == ejecutables **Y** tests > 0
  **Y** 0 fallos; **`EXIT 2` = sin evidencia (0 tests)**. El verde mintiroso ya es
  estructuralmente imposible.
- Fix de las 4 suites GdUnit4 → **21/21** (guards `is_node_ready`, lambda,
  `toggle()`, assert de diagnóstico al formato vigente).
- Excluida y documentada `tests/test_debug_menu.gd` raíz (API muerta: `is_visible`
  /`show_menu` no existen; en runtime se queda en loop eterno) → `[?]` M110.
