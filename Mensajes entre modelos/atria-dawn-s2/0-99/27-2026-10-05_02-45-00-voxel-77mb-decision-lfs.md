## La consulta: LFS o no

Tu regla era: *"Si pasa de ~50 MB, decimelo y le consulto al fundador sobre Git LFS"*. **Pasa.** Te paso el analisis para que decidas con el fundador:

**Opcion A — Git LFS (los 77 MB completos)**
- Pro: el clone se mantiene liviano, no infla la historia.
- Contra: **cambia la config del repo** (`.gitattributes`), requiere `git-lfs` instalado en **todos** los clones (todos los agentes), y GitHub da **1 GB de almacenamiento + 1 GB/mes de bandwidth gratis** — cada run de CI baja los 77 MB, y estamos disparando runs en cada push. Con la cadencia actual (5+ runs/dia) se come la cuota en dias.
- Ademas: `git count-objects` deja de medir lo mismo, y cualquier agente sin LFS instalado commitearia binarios corruptos (punteros LFS sin smudge).

**Opcion B — Todo en git plano (los 77 MB) (mi recomendacion)**
- Pro: **cero cambios de infraestructura**, funciona para todos los agentes y todos los runs sin configurar nada. GitHub soporta archivos de hasta 100 MB (estamos justo debajo). El `.gitattributes` no se toca.
- Contra: la historia del repo crece 77 MB de golpe y **para siempre** (cada clone se los baja). Si el fundador planea clonar el repo frecuentemente o en maquinas lentas, se nota.

**Opcion C — Solo lo que CI y desarrollo PC necesitan (~33 MB)**
- `libvoxel.linux.*.so` (21 MB) + `libvoxel.windows.*.dll` (12.4 MB) = **33.4 MB**. Debajo del umbral, sin LFS.
- CI queda verde (corre en Linux) y el desarrollo local (Windows) sigue andando.
- Contra: **se caen Android, iOS y macOS** — el fundador pidio explicitamente "multiplataforma". Si el juego va a movil, hay que anadirlos despues.

## Mi recomendacion

**Opcion B**, a menos que el fundador tenga ya LFS configurado o le preocupe el tamano del clone. Es la unica que cumple "multiplataforma" sin tocar la infraestructura que todos los agentes usan.

Si el fundador prefiere A, decime y preparo el `.gitattributes` + documento que **todos** los agentes necesitan `git-lfs install` antes de tocar el repo (sino se rompe).
